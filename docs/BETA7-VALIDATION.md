# v0.1.0-beta7 验证记录

## 本次变更

- 源码输入不再重新解析隐藏的富文本；新增有界的会话撤销/重做、Ctrl+Z、Ctrl+Shift+Z / Ctrl+Y 和工具栏按钮。持久历史版本仍沿用原有 SQLite / IndexedDB 机制。
- 中文组合输入期间避免将中间富文本同步回编辑器；组合结束或失焦后提交正文。应用快捷键忽略输入法组合事件。
- 代码块和行内代码中的纯文本粘贴保持字面内容，不按 Markdown 再次解释；远程图片仍不发起请求。
- 源码恢复为受支持语法后可重新进入实时编辑；脚注、HTML、注释等不支持语法保留原文，打开与导出不触发富文本重写。
- 超过 200,000 字符的文档直接进入源码模式；大纲定位不再额外排版最后一个标题后的所有正文，避免长段落输入卡顿。
- 文本导入严格识别 UTF-8（可带 BOM）、带 BOM 的 UTF-16LE / BE；统一 CRLF / CR 为 LF。无效编码和含 NUL 文本被拒绝，提示转换编码后重试。
- 新增显式选择 Markdown 文件夹：导入目录内最多 100 篇 Markdown 与所引用的 PNG / JPEG / GIF / WebP。支持嵌套相对路径、URI 空格编码、引用式图片和角括号目的地址；代码示例不被修改。
- 所选树之外的路径、绝对地址、网络地址不作为本地文件读取；原生目录遍历跳过隐藏项和符号链接。图片缺失或不支持时中止文档批次提交。
- 修复图文导入/导出替换 URL 时可能误改同名图片说明的问题，替换范围限定在实际目的地址；仍只导出一份 UTF-8 `.md`，图片嵌入 data URI，不打包文件夹。

## 限制

- 单篇 Markdown 源文件最多 128 MB；转换后正文最多 5,000,000 字符。整次导入读取数据最多 128 MB，单图最多 20 MB；目录最多 5,000 项、深度最多 16 层。
- 单文件选择不自动读取相邻文件；外部 Markdown 带相对图片时使用“导入 Markdown 文件夹”。不支持远程图片下载、SVG 或 Markdown 内的任意 HTML 图片提取。
- 导出嵌入图片的单文件 Markdown 可重新导入 Orvia；外部阅读器对 data URI 图片的显示支持各不相同。
- 组合输入回归使用合成 composition 事件验证事件处理与保存；不等同于对每种 Windows 输入法的真实人工验收。
- 本轮不宣称新增云同步、AI、其他平台、旧版 .doc 或 PDF OCR。
